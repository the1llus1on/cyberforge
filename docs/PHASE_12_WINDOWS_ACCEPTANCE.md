# Phase 12 — фізичне приймання Windows 11 x64

Статус чекліста — **PENDING OWNER ACCEPTANCE**. Вкажіть точний commit,
SHA-256 ZIP та інсталятора зі свого manifest, Windows build/edition,
тип облікового запису, модель GPU/driver, дисплеї й масштаб.
Нативні source-тести, нативний автоматизований installer smoke і
Windows Server CI мають окремі записи в PR. Приймання цього чекліста
власник записує після виконання.

## Підготовка синтетичного демо v1

1. Розпакуйте весь ZIP у шлях із пробілами та кирилицею. Звірте хеші
   ZIP й інсталятора з довіреним manifest. Запускайте під звичайним
   Windows-користувачем із чинною політикою Defender і SmartScreen.
2. З окремої копії CyberForge виконайте через PowerShell:

   ```powershell
   Start-Process .\CyberForge.exe -ArgumentList '--demo-profile','--init-demo' -Wait
   Start-Process .\CyberForge.exe -ArgumentList '--demo-profile'
   ```

   Відкрийте приватний `demo-credentials.json` у
   `CyberForge-demo-v1\lesson-v1` поряд зі звичайним профілем
   AppLocalDataLocation. Використовуйте цей файл тільки локально.
   Усі паролі створено випадково. Повторна явна ініціалізація зберігає
   профіль. Демо створює публікацію для групи А, а проходження
   створюються навчальними діями в UI.
3. Як `learner_demo_1` відкрийте лист, перевірте відправника,
   відмовтеся від переходу та завершіть. Очікування для цієї рубрики —
   SAFE_DECLINE, 100%, із незастосовною перевіркою Web.
4. Як `learner_demo_2` відкрийте лист, перевірте відправника, відкрийте
   навчальну Web-сторінку й завершіть без перевірки адреси.
   Очікування — WEB_VISITED, 33,33%. Якщо також виконати перевірку адреси,
   очікування — 66,67%. Створіть офлайн-пояснення Mentor для обох спроб.
5. Як `learner_demo_3` почніть спробу, закрийте програму, відкрийте
   demo-профіль і перевірте відновлення тієї самої спроби. Увійдіть як
   `teacher_demo_1` і перевірте історію, діаграми й CSV/JSON export.
   Викладач групи Б та інший учень не отримують ці приватні результати.

## Перенесення профілю Phase 11 (F12-PR19-01)

1. Використайте окремого Windows-користувача і синтетичну базу Phase 11 у
   `AppLocalDataLocation/cyberforge.sqlite3`. Підготуйте користувачів,
   групу, публікацію, завершену спробу, scoring і Mentor. Запишіть хеші
   DB та WAL, якщо WAL присутній після закриття старого випуску.
2. За відкритого старого випуску перевірте відмову в перенесенні. Закрийте
   його й перевірте скасування. База в `private` і bootstrap не мають з’явитися.
3. Підтвердьте перенесення. Перевірте старий пароль, ролі, публікацію,
   історичний результат, Mentor і Analytics, а також незмінні хеші старих
   файлів і резервну копію в `private/backups`.
4. Перезапустіть ZIP і встановлений випуск під тим самим Windows SID та
   повторіть запуск після перевстановлення. Перевірте, що обидва артефакти
   відкривають `private/cyberforge.sqlite3` без нового перенесення. Після
   переходу не продовжуйте роботу зі старим випуском.
5. В окремих тестових профілях перевірте відмову для двох незалежних БД,
   небезпечних файлових цілей і пошкодженої бази. Якщо залишився старий
   rollback journal, перенесення зупиняється до штатного відновлення та
   закриття БД у старому випуску. Не прибирайте журнал вручну.
