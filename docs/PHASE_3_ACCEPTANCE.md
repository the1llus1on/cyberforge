## Підготовка окремого демонстраційного профілю

Перейдіть у гілку `feat/phase-3-scenario-management`. Використайте нові
шляхи, якщо наведені вже належать іншій перевірці. Не видаляйте існуючі БД,
паролі чи native Windows acceptance workspace Phase 2.

```console
uv sync --locked
uv run cyberforge --init-demo --database .local/phase3-review.sqlite3 --credentials-file .local/phase3-review-credentials.json
uv run cyberforge --database .local/phase3-review.sqlite3
```

Логіни — SRS §2.6; пароль береться лише з нового приватного локального
credentials-файлу. Не додавайте його, БД або знімки паролів до Git/PR.
Сценарії у demo не створюються автоматично. Міграції 0002/0003 додають таблиці
версій та archive metadata; наявні користувачі/групи, ID й JSON snapshots
залишаються без змін. Не reset-ити БД; тести використовують isolated files.
Для WSLg можна додати `QT_QPA_PLATFORM=wayland` у Linux-команді запуску.
У PowerShell Windows не задавайте Wayland/offscreen для фізичного тесту.

## Перевірки

- [ ] **Guest:** доступні тільки Home, вхід/профіль і налаштування;
  каталог/Конструктор/Аналіз недоступні.
- [ ] **Створення:** увійти як teacher_demo_1 → «+» → «+ Новий сценарій».
  До натискання New центральна область показує лише «Сценарій не вибрано»
  і підказку; forms/tabs/NIST/Save/Revert/Archive/Restore приховані.
  Каталог і New доступні, сценарій/версія не створюються автоматично.
  Відкрилася форма без ID, каталог не змінився. Save із порожньою/пробільною
  темою показує помилку. Не створюється порожній запис.
- [ ] **Параметри:** тема «Навчальне повідомлення синтетичної служби підтримки»,
  будь-яка з трьох складностей, аудиторія/опис; у «Розширені» — мета, бажані
  власні тактики по рядках, позначки ознак NIST та `{"language": "uk"}`. Save створює
  «Сценарій {id}», версію 1, ревізію 1, статус «Чернетка», автора й дату.
  Тема не замінює автоматичну назву. Порожні optional поля дозволені.
- [ ] **Редагування:** змінити опис, Save. ID і версія ті самі, ревізія зросла.
  Перевідкрити картку — параметри збережені. Невалідний JSON не зберігається;
  введений текст залишається у формі для виправлення.
- [ ] **Каталог:** створити другий сценарій, перевірити різні ID; пошук за
  ID/темою/статусом приховує невідповідні рядки без зміни записів.
- [ ] **Один ID між режимами:** вибрати сценарій → Аналіз → Конструктор;
  відкривається той самий ID. Аналіз не має New/Save і показує відсутність
  результатів; оцінки, графіки, результати учнів не вигадуються.
  Повторний «+» не скидає вибір або archive filter. Після відкидання нового
  незбереженого сценарію й повернення без ID показується нейтральна заглушка.
- [ ] **Незбережені зміни:** змінити тему; спробувати інший режим/Home,
  Back/Forward, інший сценарій, New і закриття вікна. «Залишитися» зберігає
  форму й маршрут; «Відкинути зміни» не записує правки; «Зберегти» записує
  валідні параметри й виконує дію. Невалідний Save блокує перехід/закриття.
  Escape означає «Залишитися». «Скасувати зміни» окремо запитує підтвердження
  відкидання: Cancel лишає правки, підтвердження повертає актуальні saved дані
  без Save. Перевірити також перемикання archive filter із dirty формою.
- [ ] **Конфлікт:** відкрити ту саму БД і сценарій у другому процесі під тим
  самим викладачем. Перший процес зберігає правку. Застарілий Save другого
  відхилено, його текст залишився у формі; дані першого процесу не стерті.
  Скопіювати потрібні правки, відкинути застарілу форму, перевідкрити сценарій.
- [ ] **Перезапуск:** закрити й запустити застосунок із тим самим `--database`,
  увійти знову. ID, параметри, автор, дата, версія й ревізія збережені.
- [ ] **RBAC:** teacher_demo_2 не бачить сценаріїв teacher_demo_1;
  Administrator_demo бачить усі, чужі відкриває лише для читання (обидві
  вкладки доступні), власні створює/редагує. learner_demo_2 не має доступу
  до чернеток або Конструктора. Logout очищає каталог, пошук, редактор й ID.
- [ ] **Архів:** під власником вибрати збережений сценарій, «Архівувати сценарій».
  Cancel підтвердження нічого не змінює. Підтвердити; за наявності правок
  перевірити Save/Discard/Cancel. Failed/invalid/stale Save не архівує.
  Архівний запис має той самий ID/версію/ревізію; параметри read-only,
  дата архіву видима. У default active каталозі запис прихований; фільтр
  «Архівні сценарії» відкриває його в тому самому каталозі.
- [ ] **Відновлення:** перевірити пошук у архівному фільтрі, вибрати запис,
  перейти Аналіз → Конструктор: ID зберігається. «Відновити з архіву» повертає
  запис до active, редагування доступне, content version не збільшилась.
  Перезапустити також із архівним записом: він залишається в архіві.
- [ ] **Archive RBAC:** teacher_demo_2 не бачить чужого архіву; admin може
  прочитати його, прокрутити всі поля/ознаки, але Archive/Restore/Save
  недоступні. Власний admin-сценарій підтримує Archive/Restore.
- [ ] **Два екземпляри:** залишити dirty editor у другому вікні. У першому
  архівувати сценарій: друге блокує редагування, але не стирає текст (можна
  copy). Після Restore першого друге не може зберегти старий контекст навіть
  без зміни content revision. Скопіювати правки, відкинути старий буфер,
  повторно відкрити актуальну картку й перенести потрібний текст вручну.
- [ ] **NIST selector:** у «Розширені» вибрати першу/останню ознаки мишею та
  Space, прокрутити список, прочитати оригінальний English term у tooltip.
  Save → повторне відкриття → restart: вибір збережено. Це desired cues,
  наявність у контенті чи складність NIST не обчислюються. Власні тактики
  зберігаються окремо. У мігрованих legacy-записах старі рядки видимі окремо,
  не класифіковані й не видаляються під час редагування.
- [ ] **Межі фази:** Email/Web мають «Не створено»; генерації й публікації
  немає. Параметри не роблять сценарій доступним учням. Немає cloud API calls.
- [ ] **Phase12 — відкладений native Windows 11 gate (не умова поточного Phase3 WSLg acceptance):**
  перевірити форму/вкладки/archive dialogs/cue selector, українське
  введення, copy/paste, клавіатурну навігацію й читабельність при 1100×720,
  звичному розмірі й DPI100/125/150/200% у доступній конфігурації. Фіксувати
  реально перевірені масштаби, не зараховувати всю матрицю автоматично.
  Перевірити Save/Archive/Restore, обидві вкладки, scrolling cue list/форм,
  keyboard Tab/Space/Escape, копіювання з readonly/legacy fields та діалоги.
  WSLg/Windows Server offscreen не замінюють цей пункт.
  У Phase12 також виконати packaging/executable/installer, permissions,
  security, повні regression та end-to-end перевірки. До фактичних доказів
  не зараховувати native поведінку Phase3 як перевірену.
