# ADR-0001 — Головна як універсальна навігаційна сторінка

**Статус:** погоджено власником під час рев’ю Phase 1, 11.11.2026.
**Фаза:** Phase 1 — ACCEPTED власником 11.11.2026; контракт Phase 2 реалізовано для REVIEW.

## Контекст і відхилення від SRS v3.0

SRS §§3.3–3.4 описує верхні перемикачі Конструктора й Аналізу, §3.11 —
гостьове привітання. Початкова реалізація позначала сторінку привітання
`View.GUEST`, змішуючи навігаційне призначення зі станом автентифікації.

Власник явно погодив додаткову універсальну сторінку Home («Головна»)
та три верхні іконки: будинок, «+», графік. Це затверджене уточнення UI
відносно SRS v3.0, а не неявна зміна вимог. Файл SRS і його версія
залишаються незмінними. Майбутні рольові відмінності з §3.9 зберігаються.

## Рішення в Phase 1

- `View.HOME` — окремий маршрут; початкова історія завжди починається з Home.
  `AuthenticationState.GUEST` — незалежний стан оболонки, єдиний доступний
  до Phase 2. Історія переходів не змінює цей стан і не надає прав.
- Home пояснює призначення CyberForge, навчальний цикл і навігацію.
  Це інформаційна сторінка, окрема від робочих режимів.
- Точний текст огляду: «Сценарій → Електронний лист → Вебсайт → Аналіз».
  Це лише UI-огляд; Email → Web → Scoring → Feedback, детермінований
  ScoringService та правила результатів не змінюються.
- Один каталог «Сценарії» показується у Конструкторі та Аналізі;
  приховується на Home, у профілі й налаштуваннях. Повернення через історію
  відновлює видимість того самого віджета.
- Прибрано повторюване повідомлення про синтетичні матеріали з UI.
  SRS §§16, 27 та security-правила AGENTS.md залишаються чинними:
  лише синтетичні дані, ізоляція симуляції, заборона реального фішингу.
- Guest бачить лише явно позначені порожні перегляди режимів. Створення,
  пошук, захищені операції та аналітичні дані залишаються недоступними.
  Сценарії, оцінки, ролі та fake-login не додаються.

## Контракт для Phase 2 — визначений під час Phase 1

| Стан / роль | Початкова сторінка | Верхня навігація |
|---|---|---|
| Guest | Home | Home, «+» і «Аналіз» як порожні перегляди оболонки |
| Administrator | Home після входу | Home, Конструктор, Аналіз |
| Instructor | Home після входу | Home, Конструктор, Аналіз |
| Learner | Home після входу | Home, «Мої сценарії», «Мої результати» (§3.9) |

Home доступна всім і не залежить від ролі. Phase 2 має підключити реальну
сесію, формувати два робочі призначення відповідно до ролі та перевіряти
права в application services; їх не можна отримати простим переходом.
Після успішного входу слід відкривати Home й починати нову історію контекстів,
щоб не переносити захищені контексти між сесіями. Home має показувати
доречні сесії підказки замість пропозиції входу для авторизованих користувачів.
Цей контракт не є реалізацією входу, ролей чи їхніх service-level дозволів.

## Перевірки та наслідки

Unit/GUI-тести перевіряють початкову Home, незмінний Guest-стан під час
переходів, взаємовиключні активні стани, точний текст циклу, відсутність
видаленого disclaimer, історію Home ↔ робочі режими, один каталог,
клавіатуру та всі представлення у трьох розмірах вікна.
Автентифіковані рольові шляхи перевірятимуться в Phase 2 після її погодження.

## Виконання контракту у Phase 2 (11.11.2026)

Власник окремо погодив Phase 2. Контракт реалізований: реальна сесія,
Home після входу та виходу, скидання історії, рольові маршрути, доречні
Home-підказки. `tests/ui/test_accounts_ui.py` перевіряє всі три ролі,
зміну користувача й очищення попередніх контекстів. Service-level політика
знаходиться в AccountService; приховані кнопки не надають прав.
Подробиці зберігання й сесій — [ADR-0002](0002-identity-groups.md).
Статус Phase 2 — REVIEW, прийняття належить власнику.
