# CyberForge

Локальний навчальний симулятор і конструктор сценаріїв соціальної інженерії,
розроблений у межах магістерської дисертації. Цільова платформа — Windows 11;
нормативне джерело — [SRS v3.0](TECHNICAL_SPECIFICATION.md).

## Поточний стан

Phase 0 — ACCEPTED. Phase 1 — Main UI Shell: REVIEW.
Українська темна оболонка PySide6: універсальна Головна, навігація режимами,
спільна панель «Сценарії», профіль, налаштування, історія назад/вперед.

Головна містить опис платформи, навчальний цикл і підказки навігації;
каталог сценаріїв відображається у робочих режимах.
Рішення власника зафіксовано в [ADR-0001](docs/adr/0001-home-navigation.md).

Перемикачі «+» та «Аналіз» відкривають лише позначені попередні перегляди
порожньої оболонки. Гість не має доступу до сценаріїв; створення й пошук
недоступні. Авторизація, БД, AI та обчислення результатів належать наступним
фазам. Тестових користувачів, сценаріїв і оцінок немає.
Секрети, Gemini API та `.env` для запуску не потрібні.

## Встановлення й демонстрація

Потрібні Python 3.12 та [uv](https://docs.astral.sh/uv/getting-started/installation/).
У корені репозиторію (WSL або PowerShell):

```console
uv sync --locked
uv run cyberforge
```

Альтернативна точка входу: `uv run python -m cyberforge`.
`uv` створює `.venv`; перше встановлення потребує мережі.

1. Перевірте Головну, позначку «Гостьовий режим» і цикл
   «Сценарій → Електронний лист → Вебсайт → Аналіз». Каталог тут прихований.
2. Натисніть «+» у лівій панелі: відкриється Конструктор, з’явиться
   недоступна кнопка «+ Новий сценарій». Нових записів не створюється.
3. Натисніть іконку графіка: відкриється Аналіз; кнопка створення зникне.
4. Скористайтеся «Назад/Вперед», «Головна», «Налаштування», «Профіль».
   «Перейти до входу» пояснює, що авторизація ще не реалізована.
5. Змініть розмір вікна (мінімум 860×620). Для переходів кнопками можна
   використовувати Tab і Space; довгі сторінки прокручуються.

## Перевірки

```console
uv run ruff check .
uv run ruff format --check .
uv run pytest
uv run cyberforge --smoke-test
uv build
```

`--smoke-test` відкриває гостьове вікно й закриває його через цикл подій Qt.
Тести за замовчуванням використовують `offscreen`; сценарії, ключі та зовнішні
сервіси не потрібні. Для перевірок без мережі після встановлення додайте
`--offline --locked` після `uv run`, наприклад:

```console
uv run --offline --locked pytest
```

У WSLg перевірено Wayland. Для демонстрації, якщо автоматичний вибір Qt
пробує недоступний XCB backend:

```bash
QT_QPA_PLATFORM=wayland uv run cyberforge
QT_QPA_PLATFORM=wayland uv run pytest tests/ui -q
```

Для сервера без дисплея:

```bash
QT_QPA_PLATFORM=offscreen uv run cyberforge --smoke-test
```

У поточному WSL XCB не запускається через відсутню системну залежність
плагіна (`libxcb-cursor0`); Wayland працює з доступом до WSLg-дисплея.
Windows 11 ще не перевірено. На Windows потрібно перевірити звичайний
запуск, масштабування 100/125/150/200%, клавіатуру, шрифти та зміну розміру;
не встановлюйте `QT_QPA_PLATFORM=wayland` у Windows.
Qt WebEngine і MockLLMProvider належать майбутнім фазам.

## Структура та правила

- `src/cyberforge/main.py` — запуск застосунку.
- `src/cyberforge/ui/` — оболонка, сторінки, тема, іконки та історія навігації.
- `tests/` — перевірки пакета, навігації та GUI.
- `pyproject.toml`, `.python-version`, `uv.lock` — середовище та залежності.
- `docs/IMPLEMENTATION_PLAN.md` — фази й критерії прийняття.
- `docs/DEVELOPMENT_LOG.md` — рішення, фактичні перевірки та обмеження.

Локальні `.env`, бази даних, кеші та результати збирання ігноруються Git.
`.env.example` містить лише безпечні пояснення. Використовуйте виключно
синтетичні навчальні дані. Межі модулів визначені SRS §22;
порожні модулі наперед не створюються.
